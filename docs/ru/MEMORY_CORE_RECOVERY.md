# Memory Core — резервное копирование и восстановление

Статус: программная процедура описана; физическая репетиция на ноутбуке ожидает команды владельца «Выгружаем».

## Что защищаем

Основная SQLite-база JARVIS включает проекты, контрольные точки, решения, идеи и историю диалога. Приватный журнал остаётся отдельным opt-in хранилищем и не включается в экспорт проекта.

## Резервная копия

1. Остановить процессы JARVIS, которые пишут в базу.
2. Создать резервную копию в новый путь существующим методом Projects.backup(destination). Метод использует SQLite backup API и проверяет PRAGMA integrity_check.
3. Убедиться, что исходная база не была изменена и файл резервной копии существует.
4. Не хранить единственную копию рядом с исходной базой на том же физическом диске.

## Восстановление без перезаписи

1. Не восстанавливать поверх рабочей базы.
2. Использовать Projects.restore_backup(source, destination) с новым путём назначения. Метод отклоняет отсутствующий источник, совпадающий путь и уже существующий файл; проверяет целостность и наличие таблицы projects.
3. Открыть восстановленную базу через Projects(destination) и проверить список проектов, контрольные точки и следующий шаг.
4. Если в резервной копии была история диалога, открыть тот же файл через ConversationMemory(destination) и проверить несколько последних записей.
5. Переключать приложение на восстановленный файл только после проверки данных и отдельного сохранения текущей рабочей базы.

## Ограничения

- Автотесты проверяют создание копии и восстановление в новый файл на Windows и Ubuntu CI.
- Физическая репетиция на целевом ноутбуке ещё не выполнена.
- Не удалять исходную базу или резервную копию до завершения ручной проверки.
- Экспорт проекта JSON — переносимый выборочный экспорт; это не полная резервная копия истории диалогов.
